*mentor.txt*  Learning-oriented AI assistance for Neovim.

==============================================================================
INTRODUCTION                                                      *mentor.nvim*

Mentor.nvim balances observation, coaching, and explicitly requested
implementation. It is autonomous in understanding a project and deliberately
restrained in modifying it. This build provides an interactive Coach that
runs a bounded tool-calling loop against any OpenAI-compatible provider
(streaming, native tools, budgets, cancellation, request queuing), with
conversations persisted locally per project, plus project identity, local
storage, a shared access policy, read-only investigation tools
(files/buffers, Git state, diagnostics), and shared persistent memory the
assistant manages under strict user control (revisions, protection,
revert, erasure), an Implement mode that turns an explicitly selected
range in one buffer into a previewed, explicitly accepted buffer edit, and
an automatic Observer that reviews recent changes in the background —
off for every project until explicitly enabled, bounded by its own
budgets, and never able to touch the code it comments on.

Setup: >lua

    require("mentor").setup({
      providers = {
        default = {
          endpoint = "https://api.example.com/v1",
          model = "tool-calling-model",
          api_key_env = "MENTOR_API_KEY",
        },
      },
    })
<

Run `:checkhealth mentor` for actionable dependency and configuration reports.

COMMANDS                                                        *mentor-commands*

:MentorChat                 Open the Coach conversation window for the
                            current project. The transcript persists across
                            restarts. In the buffer, edit a line starting
                            with "> " and press <CR> to send it.
                            The transcript renders as Markdown (see
                            |mentor-chat-markdown|).

:MentorChatAsk {question}   Ask Coach immediately. Requests made while one
                            is running queue automatically and run in
                            order.

:MentorChatClear            Clear the stored Coach transcript for the
                            current project. Memory is not affected;
                            memory erasure likewise never touches the
                            transcript.

:MentorStop                 Cancel running operations. Late results from a
                            cancelled operation are never applied. Queued
                            requests keep their place.

:MentorStatus               Show configuration, providers, project, storage,
                            usage totals, memory totals, and active
                            operations.

:MentorMemory [args]        Without arguments, open the memory view: a
                            generated Markdown rendering (never a disk file)
                            of global and project memory entries. Edit an
                            entry's summary (first body line), content, or
                            trailing "Refs:" line and save (:w) to commit;
                            add a "## [new]" block to create an entry;
                            remove a whole block to delete one. Saves
                            validate against the revisions the view was
                            rendered at and commit in one transaction; a
                            conflicting change made elsewhere refuses the
                            whole save and keeps your proposed text in the
                            buffer. Your edits protect the entry: the
                            assistant cannot replace protected entries.
  :MentorMemory revert <id> [rev]
                            Re-apply an older revision as a new revision
                            (default: the previous one). Works for
                            undoing any change, including a deletion.
  :MentorMemory delete <id> Reversible deletion. The tombstone suppresses
                            automatic recreation of that entry.
  :MentorMemory erase <id>  Permanent removal of the entry and all of its
                            history, leaving only a content-free audit
                            marker. The Coach transcript is untouched.
  :MentorMemory protect <id> on|off
                            Re-apply or release user precedence over an
                            entry.
  :MentorMemory consolidate Run one bounded pass merging redundant
                            unprotected entries in this project.

:MentorImplement {instruction}
                            Propose a bounded edit for the current visual
                            selection (characterwise or linewise) or, with
                            no selection, the insertion point at the
                            cursor. Runs on one buffer backed by a real
                            file; off-limits and unmodifiable buffers are
                            refused. The target range is frozen before the
                            model runs; the model can only submit
                            replacement text for exactly that range. No
                            window opens: notifications report the start
                            and the outcome (proposal ready, stopped, or
                            failed). Blockwise selections are refused with
                            an explanation. :MentorStop cancels the run
                            and withdraws its pending proposal.

:MentorImplementReview [id] Open the pending proposal (newest, or the given
                            id) in a new tab page: the whole file before
                            (left) and after (right) in diff mode, with the
                            Implement log below. In the diff buffers, `a`
                            accepts, `r` rejects, and `q` closes the tab
                            while the proposal stays pending. Accepting or
                            rejecting, from the tab or by command, closes
                            the tab and returns to the window the review
                            was opened from.

:MentorImplementLog         Show the project's Implement log: one Markdown
                            buffer per project, a section per run, with the
                            model's narration, tool calls, and outcomes.

:MentorImplementAccept [id] Apply the pending proposal (newest, or the
                            given id). The target is revalidated first:
                            buffer identity, buffer version, modifiability,
                            and the current access policy. Any intervening
                            edit invalidates the proposal — even an edit
                            later undone — and so does closing the buffer.
                            Accepting performs one buffer edit in its own
                            undo block: a single `u` reverts it. The buffer
                            is never written to disk by the plugin.

:MentorImplementReject [id] Reject the pending proposal. The target buffer
                            is not touched.

:MentorObserve [action]     Control automatic observation for the current
                            project. No action toggles it. enable
                            activates it (persisted across restarts, and
                            bound to the Observer provider endpoint:
                            changing the endpoint disables it until you
                            enable again) and states once what will be
                            transmitted, including unsaved buffer content
                            inside the access policy. disable turns it
                            off and cancels running passes. pause stops
                            background passes for this session only;
                            resume re-enables them without changing the
                            persisted setting. review runs one explicit
                            pass without turning anything on.

:MentorObservations         Open the observation list for the current
                            project: every finding the Observer recorded,
                            newest first, with its category, certainty,
                            reasoning, referenced files, and a staleness
                            mark recomputed from stored fingerprints.
                            With the cursor on a finding: d dismiss,
                            r restore, u useful, x not useful, s snooze
                            the category (30 minutes), m mute/unmute the
                            category, <CR> ask Coach to explain it,
                            R refresh, q close.

:MentorExplain [id]         Ask Coach to explain an observation (by id,
                            or the newest active finding), opening the
                            Coach conversation with its full context.

CONFIGURATION                                                *mentor-config*

See README.md for the current reference. Shipped defaults for limits,
notification cadence, context sizes, and observation timing are validated at
setup(); invalid values produce named, actionable errors.

context.exclusions       Additional glob patterns excluded from every
                         context source (buffers, traversal, searches, Git
                         output). Built-in credential defaults (.env,
                         .env.*, private keys, .git-credentials, ...) are
                         always excluded and cannot be re-allowed here.
projects.external_dirs   Roots beyond the project root that file tools may
                         read. Empty by default.
providers.default.*      endpoint, model, api_key_env, timeout_s,
                         max_tokens (completion cap; raise it for reasoning
                         models), capabilities = { tools, streaming }.
chat.history_max_tokens  Conversation history sent with each request is
                         trimmed oldest-first to this estimated budget.
chat.markdown            Render the Coach transcript as Markdown
                         (default true). See |mentor-chat-markdown|.
chat.align_tables        Pad Markdown table columns in replies to a
                         common width (default true).
memory.recall_limit      Entries injected into a model request (global +
                         current project, provenance-authorized) and
                         returned by memory searches.
memory.recall_max_bytes  Byte cap on the memory block appended to the
                         system context.
memory.consolidate_max_entries
                         Candidate entries considered per manual
                         :MentorMemory consolidate pass.
memory.view_max_entries  Entries rendered in the :MentorMemory view
                         (newest first).
implement.max_target_bytes
                         Byte cap on the range captured by
                         :MentorImplement; larger selections are refused.
implement.max_replacement_bytes
                         Byte cap on a proposed replacement.
observer.edit_idle_ms    Automatic passes start this long after the last
                         edit in a project buffer (TextChanged).
observer.save_debounce_ms
                         Shorter debounce used after a save instead.
observer.notify_cooldown_ms
                         Per-finding cooldown: a dismissed finding that
                         is re-confirmed waits this long before it may
                         interrupt again (default ten minutes).
observer.notify_min_gap_ms
                         At most one unsolicited notification per project
                         per this interval (default one minute).
observer.category_snooze_ms
                         Duration of the observation-list "snooze
                         category" action (default thirty minutes).
observer.notify_learning Learning-category findings notify only when
                         this is on (default off; they always stay in
                         the list).
observer.digest_total_bytes
                         Byte cap on the change digest composed for each
                         pass.
observer.digest_file_bytes
                         Per-file cap inside the digest.
observer.list_max_items  Findings rendered in :MentorObservations.
limits.background.*      Background budgets, enforced across all
                         instances through local storage:
                         requests_per_hour_per_project and
                         est_tokens_per_day_per_project gate every
                         automatic pass for the project.

Local data lives in stdpath("data")/mentor; credentials are read from the
environment at request time and are never stored.

COACH MARKDOWN                                          *mentor-chat-markdown*

The Coach buffer (filetype "mentorchat") is highlighted with Neovim's
bundled treesitter Markdown parser: headings, emphasis, inline code, links,
lists, tables and fenced code blocks (with injected highlighting for the
block's language). Chat windows use 'conceallevel' 2, so emphasis and code
markers are hidden except on the cursor line. Tool activity and status
lines use MentorChatNote (linked to Comment); lines starting "⌁ error:" use
MentorChatError (linked to DiagnosticError).

Pipe tables in a reply are aligned once the reply finishes streaming:
every column is padded to its widest cell, measured as displayed (concealed
markers removed, wide characters counted by display width), and the
delimiter row is rebuilt to match, keeping column alignment colons. Tables
inside fenced code blocks are left alone. Only the view changes; the stored
transcript keeps the model's text. On the cursor line concealed markers
reappear, so that one row may look offset. Disable with
`chat.align_tables = false`.

Markdown renderers that attach by filetype can provide richer output, for
example render-markdown.nvim with: >lua
    file_types = { "markdown", "mentorchat" }
<
Set `chat.markdown = false` to keep the buffer plain.

CONTEXT AND PRIVACY                                        *mentor-privacy*

Investigation tools are read-only and fixed: the model chooses among them
but never controls commands, flags, or shells. Access is decided by
resolved-path containment — a path must resolve (following symlinks) to
inside the project root or a configured external directory. The .git
directory, nested repositories (separate projects), and credential-style
files are never reachable through file tools; Git information comes only
from constrained status/diff/history adapters, labeled as disk/index views
so unsaved edits are never implied.

File tools prefer live buffer content over disk content, so unsaved (even
never-saved) named buffers are visible to investigation, and their content
is tracked: later buffer edits, external file changes, configuration
changes, or a checkout change invalidate recorded work.

Detected secrets (private-key blocks, known credential formats,
credential-style assignments) in any tool result are redacted before the
result is returned, logged, or stored. Detection is best effort; exclusions
remain the primary protection. Tests use only synthetic secrets.

Stored tool results carry their provenance and are re-authorized against
the current access policy before every model request: results from a path
that became excluded are withheld from later requests, never silently
replayed. The same recheck applies per entry inside stored memory tool
results, and to memory retrieved for a request: an entry whose referenced
path is now excluded is omitted rather than retransmitted.

Memory writes use a dedicated tool interface confined to memory storage;
the model has no file-writing tool. Stored entries are sanitized for
detected secrets, keep full revision history, mark inferences about the
developer as hypotheses, and refuse agent changes to entries the user
edited or protected. Deletion is reversible and suppresses automatic
recreation; only explicit erasure removes content, leaving content-free
audit metadata. Coach transcripts are stored locally, sanitized, and only
sent back to the configured provider; clearing them is a separate,
explicit action. Each model request reserves its budget atomically before
dispatch; limits (requests, tool calls, estimated tokens, wall-clock) are
enforced up front and interrupted work stays accounted for.

The only route from the model to your buffers is the Implement workflow. A
developer command freezes one target (buffer, range, version) before the
model runs; the model's single implement tool takes no path or range
parameters — unknown parameters are rejected — so it cannot retarget or
widen the change. Nothing is applied until a separate explicit accept,
which revalidates buffer identity, version, modifiability, and the current
access policy; any intervening edit (even edit-and-undo) or buffer close
invalidates the proposal. Application is one buffer edit in its own undo
block, never a disk write, and generated code is never executed. Coach is
never offered the implement tool at all: per-mode tool allow-lists keep the
groups separate.

The Observer is strictly read-only and opt-in. Observation stays off for a
project until :MentorObserve enable, and the activation is stored together
with the Observer provider endpoint: a changed or removed endpoint flips
it back off (persisted, with a visible notice) until explicitly enabled
again. Automatic passes build a change digest — diffs against HEAD plus
live modified-buffer content — already filtered by the access policy
(excluded files are counted, never transmitted) and capped in size;
digest, tool results, and findings go through the same sanitization as
every other source. Publication revalidates everything: finding refs are
re-authorized against the current policy (a claim resting on a newly
excluded path is withheld), and if a source, the checkout, or the policy
moved while the pass ran, the result is stored marked stale and never
notifies. Late or cancelled results can never publish. Findings are
advice only: the Observer has no editing tool, and its notifications are
deduplicated, rate-limited, held back while typing (delivered when you
leave Insert mode), and fully controllable (dismiss, mute, snooze) from
the observation list, which also says why a quiet finding didn't notify.
Background passes run on their own tighter budgets with per-project hourly
request and daily token caps enforced across all instances, and
interactive work always preempts them.
